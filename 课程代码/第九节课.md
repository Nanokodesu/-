# 第七章 三维模型（二）——模型交互渲染

## 核心概念
前一章（第六章）获取的是建筑要素本身的信息（在切片时自带的属性），本章则要对建筑进行**交互式修改**——直接改变建筑表面的颜色、透明度等样式，而不是通过前期切片的数据更改，而是通过Cesium的API接口来做渲染实现。

## 三个核心功能

### 功能1：按建筑类型分类设色
- 逻辑：识别不同建筑类型 → 告诉不同类型应该是什么颜色 → 修改属性
- 同时需要配套的图表展示（与三维可视化并行展示）
- 两件事并行：①修改3D属性 ②添加统计图表

### 功能2：按位置距离分类设色
- 应用场景：可达性分析、适老化/儿童友好型系统
- 例如：5分钟/10分钟步行可达范围
- 逻辑：选择一栋建筑 → 实时计算与其他所有建筑的距离 → 判断距离落在哪个范围 → 设置对应颜色

### 功能3：按需求渲染同类建筑
- 例如：选择学研楼，把北京范围内所有具有教学功能的楼全提取出来
- 逻辑：选择建筑 → 识别类型 → 与范围内所有建筑的类型一一比对 → 匹配则修改属性

**三个功能的共同落脚点：修改建筑的属性（全部使用Cesium3DTileStyle API）**

// 按位置距离分类设色
function colorbyDistance(pickedLongitude, pickedLatitude) {
    const tilesetStyleDistance = new Cesium.Cesium3DTileStyle({
        defines: {
            // 计算距离
            distance: "distance(vec3(${Longitude}, ${Latitude}, 0.0), vec3(" + pickedLongitude + ", " + pickedLatitude + ", 0.0))"
        },
        color: {
            conditions: [
                ["${distance} < 0.00045", "color('CRIMSON',0.9)"],                               /*注意单位为经纬度距离, 50m*/
                ["${distance} >= 0.00045 && ${distance} < 0.0018", "color('CORNFLOWERBLUE',0.9)"],       /*200m*/
                ["${distance} >= 0.0018 && ${distance} < 0.0045", "color('DARKSEAGREEN',0.9)"],          /*500m*/
                ["${distance} >= 0.0045", "color('CORNSILK',0.9)"],
            ],
        },
    });
    tileset.style = tilesetStyleDistance;
}

// 获取目标建筑的位置信息
const handler = new Cesium.ScreenSpaceEventHandler(viewer.scene.canvas);
function getCoordinate() {
    handler.setInputAction(function (event) {
        const pickedObject = viewer.scene.pick(event.position);
        if (Cesium.defined(pickedObject)) {
            const pickedLongitude = parseFloat(pickedObject.getProperty('Longitude'));    // 保证经度为浮点数
            const pickedLatitude = parseFloat(pickedObject.getProperty('Latitude'));
            colorbyDistance(pickedLongitude, pickedLatitude);
        }
    }, Cesium.ScreenSpaceEventType.LEFT_CLICK);

}

### ⚠️ 重要Bug：距离计算的经纬度单位问题
- `distance`函数计算的是**经纬度之间的距离**，单位是**度**，不是米！
- 代码中`0.00045`是经纬度单位，约等于50m（0.01度 ≈ 1.11km）
- 0.00045 × 111000 ≈ 50m，0.0018 × 111000 ≈ 200m，0.0045 × 111000 ≈ 500m
- **小尺度**（如校园范围）误差很小，可以接受
- **大尺度**（市级、省级）经纬度南北和东西跨度差异大，误差会非常大
- 大尺度项目应转换为投影坐标系（如UTM）后再计算距离

## 2. 卷帘对比

### 概念
- 最简单的三维合成功能
- 本质是**模型对比**：现状地块模型 vs 设计模型的对比
- 常见于可视化大屏展示（现状与设计方案的对比性展示）
- 不是靠按钮切换，而是**实时的左右对比**（拉住滑块左右滑动）

### 示例：香港对比
- 左边显示真实的贴图模型（现在），右边显示白膜模型（过去）
- 滑块拖动可以看到十几年的建筑变化

### DIV容器
- 卷帘对比界面是**2个div**：Cesium容器 + 滑块（slider）
- 滑块是在Cesium之上添加的一个额外div

### OSM白膜API
- 可以用老师切的白膜，也可以用OSM内置的全球白膜
- OSM白膜缺点：①网络不稳定 ②数据比较旧
- 加载OSM白膜：`Cesium.createOsmBuildingsAsync()`（自动调用API）

### 分屏API
- `SplitDirection.LEFT` / `SplitDirection.RIGHT` 控制左右分屏
- 现在的API可能已经支持3分屏

```JavaScript
 // 添加3D Tiles
(async function () {
    const LeftTileset = await Cesium.Cesium3DTileset.fromUrl(
        "./Data/OSGB/Slice_HK_11-SW-4D/tileset.json", {
        maximumScreenSpaceError: 128,       //最大的屏幕空间误差
    }
    );
    viewer.scene.primitives.add(LeftTileset);
    LeftTileset.splitDirection = Cesium.SplitDirection.LEFT;        // 两侧展示，放在左侧

    viewer.zoomTo(LeftTileset);

    const RightTileset = await Cesium.createOsmBuildingsAsync();
    viewer.scene.primitives.add(RightTileset);
    RightTileset.splitDirection = Cesium.SplitDirection.RIGHT;        // 两侧展示，放在右侧
})();

// 保证模型分割位置与滑块分割线一致
const slider = document.getElementById("slider");
viewer.scene.splitPosition = slider.offsetLeft / slider.parentElement.offsetWidth;      // 分割位置占父元素宽度的位置

// 左右两侧模型变化函数
let moveActive = false;
function move(movement) {
    if (!moveActive) {
        return
    } else {
        const relativeOffset = movement.endPosition.x;
        const splitPosition = (slider.offsetLeft + relativeOffset) / slider.parentElement.offsetWidth;
        slider.style.left = `${100.0 * splitPosition}%`;
        viewer.scene.splitPosition = splitPosition;
    }
}

const handler = new Cesium.ScreenSpaceEventHandler(slider);            // 监听滑块上的鼠标事件

handler.setInputAction(function () {
    moveActive = true;
}, Cesium.ScreenSpaceEventType.LEFT_DOWN);
handler.setInputAction(move, Cesium.ScreenSpaceEventType.MOUSE_MOVE);
handler.setInputAction(function () {
    moveActive = false;
}, Cesium.ScreenSpaceEventType.LEFT_UP);
```

### 滑块移动原理详解

**初始位置计算：**
- 滑块初始在正中心 = 50%位置
- `slider.offsetLeft / slider.parentElement.offsetWidth` = 左侧占比 / 总宽度
- 电脑识别的是**百分比**，不是像素绝对坐标

**移动函数：**
- 初始左侧占比 + 鼠标移动量 = 当前左侧占比
- 鼠标左移 → 移动量为负数 → 左侧占比减小
- 鼠标右移 → 移动量为正数 → 左侧占比增大
- 计算结果是**小数**，需转换为**百分数**给Cesium的splitPosition

**关键：事件绑定在slider而非viewer**
- `new Cesium.ScreenSpaceEventHandler(slider)` — 绑定在滑块上
- 之前课程的鼠标事件都绑定在`viewer.scene.canvas`（整个屏幕）
- 绑定在slider上，坐标变化是相对于滑块的，才能用移动量和滑块左侧占比做加和
- 如果绑定在viewer上（全局事件），坐标是相对于屏幕左上角的，会报错

**⚠️ 交互缺陷：左键拖拽冲突**
- Cesium默认鼠标左键有平移/旋转功能
- 导致在影像上点击也会拖拽影像，而不是只在滑块上滑动
- 解决：**禁用左键拖拽**，在代码最后添加一行

```javascript
// 禁用左键拖拽，只保留滑块的滑动功能
viewer.scene.screenSpaceCameraController.enableRotate = false;  // 禁用旋转
// 或者更精确地控制：
viewer.scene.screenSpaceCameraController.tiltEventTypes = [];   // 按需调整相机事件
```
